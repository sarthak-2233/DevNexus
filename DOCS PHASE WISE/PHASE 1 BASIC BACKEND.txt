Phase 1: Build the backend first
We'll build your AI website builder step by step, assuming you're starting as a beginner. We won't jump into multi-agent systems, Qdrant, or complicated LangGraph workflows yet. First, we'll build a working backend that accepts a user's request, sends it to Gemini, and returns a website-generation result.
Yes, keep the frontend and backend in separate folders. Since you're using React and Tailwind for the frontend and Node.js with Express for the backend, this is a clean structure for your project.
1. Understand the architecture
Frontend — React + Tailwind CSS
The interface where users describe the website they want.
Build later

HTTP request / JSON response

Backend — Node.js + Express
Receives requests, validates input, calls Gemini, and returns results.
Build first


Gemini API
Generates the initial website plan and code.


The backend will work independently of the frontend. We'll test it using an API testing tool or the terminal before connecting React.
2. Create your project folders
Open your terminal in the location where you want to keep the project. Run:
mkdir webforge-ai
cd webforge-ai

mkdir backend frontend
cd backend
npm init -y


Your initial folder structure will look like this:
webforge-ai/

backend/
Express API, Gemini integration, business logic, and tests.


frontend/
React, HTML, Tailwind CSS, and the user interface — later.




Why separate them?
- Each can have its own dependencies and package.json.
- Your Gemini API key stays on the backend, not in browser code.
- You can develop and test the API before the UI exists.
- Later, React can communicate with Express through HTTP requests.
3. Set up the backend folder structure
Inside backend, we'll create a simple structure that's easy to understand and can grow later.
Run these commands from the webforge-ai/backend folder:
mkdir src

4. Install the backend dependencies
In your terminal, make sure you're inside webforge-ai/backend, then run:
npm install express cors dotenv @google/genai
npm install --save-dev nodemon


What these packages do:
Package	Purpose
express	Creates your backend API
cors	Allows your future React app to call the API
dotenv	Loads environment variables from .env
@google/genai	Connects your backend to Gemini
nodemon	Automatically restarts the server when files change
Now open package.json. Keep the dependencies that npm installed and update the scripts section and add "type": "module" so it looks like this overall:
{
  "name": "backend",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "start": "node src/server.js",
    "dev": "nodemon src/server.js"
  }
}


Important: Don't replace the entire package.json with that snippet if it would remove your dependencies and devDependencies. Add "type": "module" and update only "scripts" in the existing file.
5. Create your environment variables
Create a file named .env in the backend folder:
PORT=5000
GEMINI_API_KEY=put_your_real_gemini_api_key_here


Get your API key from Google AI Studio and replace the placeholder.
Also create .env.example:
PORT=5000
GEMINI_API_KEY=


Create a .gitignore file in backend:
node_modules/
.env


Security rule: Never put your Gemini key in React code, commit it to Git, or share it in screenshots. The backend uses it privately.
6. Build your first Express server
Open backend/src/server.js and add:

import express from "express";
import cors from "cors";
import dotenv from "dotenv";

import websiteRoutes from "./routes/websiteRoutes.js";

dotenv.config();

const app = express();
const PORT = process.env.PORT || 5000;

// Middleware
app.use(cors());
app.use(express.json({ limit: "1mb" }));

// Basic API test
app.get("/api/health", (req, res) => {
  res.json({
    success: true,
    message: "WebForge AI backend is running!",
  });
});

// Website generation routes
app.use("/api/websites", websiteRoutes);

// Handle unknown routes
app.use((req, res) => {
  res.status(404).json({
    success: false,
    message: "Route not found",
  });
});

// Start server
app.listen(PORT, () => {
  console.log(`Backend running at http://localhost:${PORT}`);
});



Don't worry about every line right now:
- express() creates your application.
- express.json() lets the server read JSON request bodies.
- /api/health gives us a simple way to test the server.
- /api/websites will contain the website-generation endpoint.

Create src/controllers/websiteController.js:

import { generateWebsiteContent } from "../services/geminiService.js";

export async function generateWebsite(req, res) {
  try {
    const { prompt } = req.body;

    if (typeof prompt !== "string" || !prompt.trim()) {
      return res.status(400).json({
        success: false,
        message: "Please provide a website description.",
      });
    }

    if (prompt.length > 5000) {
      return res.status(400).json({
        success: false,
        message: "The description must be 5000 characters or fewer.",
      });
    }

    const result = await generateWebsiteContent(prompt.trim());

    return res.status(200).json({
      success: true,
      data: result,
    });
  } catch (error) {
    console.error("Website generation failed:", error.message);

    return res.status(500).json({
      success: false,
      message: "Website generation failed. Please try again.",
    });
  }
}



Create src/services/geminiService.js:

import { GoogleGenAI } from "@google/genai";

const apiKey = process.env.GEMINI_API_KEY;

const ai = apiKey ? new GoogleGenAI({ apiKey }) : null;

export async function generateWebsiteContent(prompt) {
  if (!ai) {
    throw new Error("GEMINI_API_KEY is not configured.");
  }

  const response = await ai.models.generateContent({
    model: "gemini-2.5-flash",
    contents: `
You are an expert website planner.

Analyze the user's website idea and return a clear website plan.
Include:
1. Website purpose
2. Target audience
3. Recommended pages
4. Features
5. Suggested visual style
6. A suggested layout for the homepage

Do not claim that you have created or deployed a website.
For this first version, return a plan only.

User's idea:
${prompt}
`,
  });

  return {
    websitePlan: response.text,
  };
}



This first endpoint returns a website plan, not finished website files. That's intentional: we'll first verify that our API and Gemini integration work before teaching the backend to generate actual files.
